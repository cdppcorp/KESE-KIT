> 범위: 목록.csv 519건 중 비패치 91건(보안 조치·강화 권고 18, 취약점 조치 권고 7, 주의 권고 63, 기타 3). 상단 고정 게시물 5건은 번호가 없어 `공지`로 표기합니다.

## 사용법
- 점검 대상 환경에 해당하는 섹션만 고릅니다: A 서버, B 웹, C 개발·CI/CD, D 네트워크 장비·NAS, E 보유 제품, F 업무 단말·계정, G 임직원 인식 교육 자료.
- TR 항목 하나가 점검 단위 하나입니다. 체크 결과를 **양호 / 부분이행 / 취약 / 해당없음**(대상 제품·환경이 없을 때) 중 하나로 판정합니다.
- 명령어는 공지·첨부에 있는 그대로 옮겼습니다. KISA 주의사항에 따라 운영 시스템에서 실행하기 전에 사내 정책 위반 여부와 시스템 영향을 확인하세요. "(첨부 기준)"은 첨부 PDF에서 가져온 사실이라는 뜻입니다.
- IOC(해시·IP·도메인)는 시간이 지나면 무효가 되므로 본문에 싣지 않고, 첨부 파일명과 IOC 개수만 적었습니다.

## A. 서버·시스템 침해 대응

### TR-01 BPFDoor 백도어 감염 점검
- **공지**: 2025-05-12 · #2210 · 보안 조치·강화 권고 — BPFDoor 악성코드 점검 가이드 배포 / 관련 IOC 공지: 2025-04-25 · #2193, 2025-05-03 · #2198 · 주의 권고 — 최근 해킹공격에 악용된 악성코드(, IP 등) 위협정보 공유 및 주의 안내
- **대상**: Linux 서버. #2198은 통신사 침해사고 대응 중 확인된 리눅스 공격 사례입니다.
- **배경**: 포트를 열지 않고 BPF 필터로 매직패킷을 기다렸다가 셸을 연결하는 백도어입니다. 가이드의 YARA 룰 hash 메타데이터 4건은 #2193에서 공유된 파일 해시와 같습니다.
- **점검 항목** (root/sudo 필요, 첨부 기준):
  - [ ] `/var/run/` 아래 0 byte·권한 644인 `*.pid`/`*.lock` 파일
    ```
    $ sudo ls -l /var/run/*.pid | awk '$5 == 0 {print $9}'
    $ sudo ls -l /var/run/*.lock | awk '$5 == 0 {print $9}'
    ```
  - [ ] `/etc/sysconfig/`의 자동 실행 구문(`[ -f “악성코드 경로” ] && “악성코드 경로”` 형태)
    ```
    $ sudo grep -Er '\[\s*-f\s+/[^]]+\]\s*&&\s*/' /etc/sysconfig/
    ```
  - [ ] BPF 필터의 매직넘버(Kernel 3.2 이상 + iproute2 4.0 이상 필요, CentOS 6.x 이하는 RAW 소켓 점검으로 대체)
    ```
    $ sudo ss -0pb | grep -E "21139|29269|960051513|36204|40783"
    ```
  - [ ] RAW 소켓 사용 프로세스와 실행 경로(파일이 삭제된 채 메모리에서 동작하면 예: `/dev/shm/kdmtmpflush (deleted)`로 표시)
    ```
    $ sudo lsof 2>/dev/null | grep -E "IP type=SOCK_RAW|IP type=SOCK_DGRAM" | awk '{print $2}' | sort -u | xargs -r ps -fp
    $ sudo ls -l /proc/<PID>/exe
    ```
  - [ ] HOME=/tmp, HISTFILE=/dev/null, MYSQL_HISTFILE=/dev/null을 모두 가진 프로세스([붙임2] `bpfdoor_env.sh`)
  - [ ] 포트 42391~43390·8000 사용 여부(`sudo netstat -tulpn`), 위장 프로세스명(/usr/sbin/abrtd, /sbin/udevd, cmathreshd, /sbin/sgaSolAgent, /usr/sbin/atd, pickup)과 실제 실행 경로의 일치 여부
  - [ ] 의심 파일은 strings로 초동 점검한 뒤 [붙임3] `bpfdoor.yar`(ELF_BPFDoor, ELF_BPFDoor_Controller)로 2차 검증합니다. 디렉터리 전체를 YARA로 스캔하면 장애가 날 수 있으므로 파일을 복사해서 점검합니다.
  - [ ] 네트워크 매직 시퀀스(UDP·ICMP 0x7255, 0x9F4F / TCP 0x5293, 0x39393939, 0x8D6C), HTTP POST URI의 마커 `9999`
- **조치**: 흔적이 나오면 보호나라에 침해사고를 신고합니다. 매직 시퀀스 하나만으로 만든 룰은 오탐 가능성이 있어 내부 검토 후 커스텀해야 합니다. 가이드 안의 단계 번호 상호참조가 일부 맞지 않습니다("(6)/(7)"과 "(8)/(9)" 혼용).
- **출처**: https://www.boho.or.kr/kr/bbs/view.do?bbsId=B0000133&menuNo=205020&nttId=71754 · 첨부: 250512_KISA_BPFDoor_악성코드_점검_가이드.pdf(스크립트 2종, YARA 룰 포함) / #2193 https://www.boho.or.kr/kr/bbs/view.do?bbsId=B0000133&menuNo=205020&nttId=71726 (IOC: IP 1, 파일 4) / #2198 https://www.boho.or.kr/kr/bbs/view.do?bbsId=B0000133&menuNo=205020&nttId=71735 (IOC: 파일 8) · 첨부: 없음

### TR-02 리눅스 커널 루트킷 점검
- **공지**: 2025-12-11 · #2322 · 보안 조치·강화 권고 — 리눅스 커널 루트킷 점검 가이드 배포
- **대상**: 레드햇 계열 Linux(RHEL, CentOS 등), 파일시스템 XFS/EXT2/EXT3/EXT4/BTRFS. 유닉스 계열은 지원하지 않습니다(첨부 기준).
- **배경**: 커널 루트킷이 부팅/서비스 스크립트와 백도어를 일반 사용자 명령어로는 보이지 않게 숨깁니다. 감염 증상 예시는 루트킷(was-patch)과 백도어(was_sys_relay) 은닉입니다(첨부 기준).
- **점검 항목** (첨부 기준):
  - [ ] KISA 공식 점검 스크립트(첨부 ZIP)를 root 권한과 실행 권한을 주고 실행합니다. POSIX 환경은 `rootkit_detect_scanner_posix_v1.0.sh`를 씁니다.
    ```
    ./rootkit_detect_scanner_v1.0.sh
    ```
  - [ ] 결과 판정: 정상 `[OK] No Hidden Entry | Rootkit Not Found | Backdoor Not Found` / 비정상 `[ALERT] Hidden Entry Found! | Suspicious Rootkit Found! | Backdoor Found!` → 비정상이면 출력된 의심 파일을 추가 점검합니다.
  - [ ] 점검 경로는 `/etc/systemd/system/`, `/etc/init.d/`, `/etc/rc2.d/`, `/etc/rc3.d/`, `/etc/rc5.d/`입니다. 사내에 다른 자동실행 경로가 있으면 스크립트를 수정한 뒤 실행합니다.
  - [ ] 원리: 아이노드·데이터블록으로 얻은 파일 목록과 `ls` 결과의 차집합으로 숨겨진 스크립트를 찾고, 루트킷·백도어의 경로·해시·프로세스를 터미널과 `*.log`에 출력합니다.
  - [ ] 전반 점검이 필요하면 KISA 리눅스 해킹진단도구를 쓰고, 백신·EDR과 모니터링 체계를 갖춥니다.
- **조치**: 침해가 확인되면 보호나라에 신고합니다(https://www.boho.or.kr/kr/report/list.do?menuNo=205034).
- **출처**: https://www.boho.or.kr/kr/bbs/view.do?bbsId=B0000133&menuNo=205020&nttId=71917 · 첨부: 20251212_리눅스_커널_루트킷_점검_가이드.pdf(v1.0-rev1, 2025.12.12 BTRFS 추가), rootkit_detect_scanner_v1.0-rev1.zip(KISA 공식 도구, 본 문서 작성 시 압축 해제·실행하지 않음)

  - [ ] 기본 서비스 포트(22, 1433, 3389 등) 노출을 지양하는지. 외부 접속이 필요하면 IP·단말 제한, MFA, 서버별 접근제어를 적용하고 로그(해외·야간·주말 IP, 평소와 다른 통신량)를 주기적으로 보는지. 유지보수 업체 접속은 필요할 때만 허용하는지
  - [ ] 계정: 기본 관리자 비밀번호 변경, 미사용 기본 계정 비활성화, 복잡한 비밀번호와 정기 변경, 2차 인증, 원격접속 계정정보 평문 저장 금지
  - [ ] 백업: 네트워크와 분리된 저장소에 정기 백업(같은 저장소에 두었다가 함께 암호화된 사례 다수), 클라우드에 둔 자료도 별도 백업
  - [ ] 메일: 확장자 표시(파일 탐색기 > 보기 > '파일 확장명'), 격리 환경에서 첨부 확인, 메일 보안 솔루션. 관리자는 비인가 계정·비정상 로그인을 점검하고 평문으로 오간 계정정보를 바꿨는지
  - [ ] AD: 특권 관리자 계정 분리와 자격증명 주기 관리, 관리자 단말 보호와 접속경로 통제, 특권 인증·비정상 서비스 설치에 대한 중앙 로그 모니터링

### TR-11 PHP2Shell(CVE-2026-109618, CVE-2026-109619) 기업 대응 수칙
- **공지**: 2026-10-22 · 공지 · 취약점 조치 권고 — PHP 보안취약점(PHP2Shell) 관련 기업 보안 대응 수칙

- **배경**: 로그인 없이 원격에서 명령을 실행할 수 있는 취약점입니다(CVSS 9.2). 패치 전에 정보가 유출돼 공격 시도가 보고됐습니다. 서버 메모리에 있는 비밀번호·토큰·API 키도 유출될 수 있습니다.
- **점검 항목**:
  - [ ] 자산 목록이 아니라 실제 동작 중인 서버 기준으로 PHP 사용 여부와 버전을 파악합니다. 외주·방치·이벤트·테스트 서버, 관리자 페이지, PHP 내장 장비·윈도우 설치 패키지, 외부 컨테이너 이미지도 포함합니다.
  - [ ] 해결 버전 PHP 8.5.12, 8.4.27, 8.3.36, 8.2.35 이상(리눅스 배포판·제조사 업데이트 포함)을 인터넷 공개 서버부터 적용합니다.
  - [ ] 업데이트 후 PHP-FPM, Apache mod_php, php-cgi, FrankenPHP, LiteSpeed 등 PHP를 실행하는 모든 서비스를 재시작합니다(안 하면 여전히 취약). 컨테이너는 새 이미지로 재배포합니다.
