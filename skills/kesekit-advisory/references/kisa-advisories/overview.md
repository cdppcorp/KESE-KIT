# KISA Security Notice Data Overview

Structured data collected from the KISA Boho-nara (KrCERT/CC) security notice board. It backs exposure checks, notice briefings, CVE lookups, and threat-response checks.

## Source

- Board: KISA Boho-nara security notices — https://www.boho.or.kr/kr/bbs/list.do?bbsId=B0000133&menuNo=205020
- Archive in this repo: `문서/KISA_보안공지_2025-2026/` (`목록.csv` index + per-notice `본문.html`/`본문.txt`/attachments)
- Notices are published in Korean. Titles, summaries, and table cells stay in Korean; product names, versions, and CVE IDs are language-neutral.

## Notice types and how this skill uses them

| Type (Korean label) | Meaning | Used for |
|---------------------|---------|----------|
| 보안 업데이트 권고 (Security update advisory) | Vendor patch release. Usually has a `CVE \| Product \| Affected versions \| Fixed versions` table | Exposure check (`advisories.json`) |
| 취약점 조치 권고 (Vulnerability mitigation advisory) | Interim mitigations, security-software clean-up, response rules (e.g. PHP2Shell, FreeType) | Exposure check + threat response |
| 보안 조치·강화 권고 (Hardening advisory) | Incident / malware response checks (BPFDoor, Linux kernel rootkits, ransomware, exposed credentials, …) | Threat response (`threat-response.md`) |
| 주의 권고 (Caution advisory) | Product-use cautions (EoL / stop using), dev supply-chain attacks, phishing/smishing | Threat response |
| 기타 (Other) | US CISA KEV sharing, impersonation case reports | Reference |

## advisories.json schema (schema 1)

```
{
  "schema": 1,
  "source": "...",
  "coverage": {"first": "YYYY-MM-DD", "last": "YYYY-MM-DD", "count": N},
  "risk_sources": {"kev": {"version": "2026.11.10"}, "epss": {"date": "2026-11-13"}, "nvd": {"fetched": N}},
  "cve_meta": {                ← per-CVE risk signals, one CVE per line (scripts/fetch_cve_enrichment.py)
    "CVE-2025-0282": {"kev": "2025-01-08", "ransomware": true,     ← CISA KEV date added, ransomware use
                      "epss": 0.99981, "pct": 0.99981,             ← FIRST EPSS score and percentile
                      "cvss": 9.0, "cvss_v": "3.1", "sev": "CRITICAL", "cwe": ["CWE-787"]}   ← NVD (with --nvd)
  },
  "advisories": [            ← newest first, one notice per line
    {
      "no": "2632",           ← Boho-nara post number ("공지" for pinned posts)
      "ntt": "72304",         ← nttId from the source URL (unique key, accepted by --id)
      "date": "2026-11-12",
      "type": "보안 업데이트 권고",
      "title": "Apache 제품 보안 업데이트 권고",
      "vendor": "Apache",     ← vendor normalised from the title ("기타" = unclassified)
      "url": "https://www.boho.or.kr/...",
      "folder": "2026/11/...",
      "attachments": [],
      "summary": "Description section, max 500 chars",
      "refs": [{"n": "1", "url": "https://www.php.net/..."},   ← □ 참고사이트 [n] references (visible body)
               {"url": "https://..."}],                      ← other body URLs without a number (vendor downloads, …)
      "cves": ["CVE-..."],
      "affected": [           ← notice tables flattened per row (rowspan/colspan expanded)
        {"cve": "...", "vendor": "...", "product": "...", "ecosystem": "npm",
         "affected": "2.4.55 이상 2.4.71 미만", "fixed": "2.4.71 이상",
         "severity": "...", "description": "..."}
      ],
      "text": "body text (URLs removed, max 4000 chars) — for finding products mentioned outside the table",
      "tables": [{"header": [...], "rows": [[...]]}]   ← tables whose columns could not be mapped (optional)
    }
  ]
}
```

A row only carries the columns its table had; not every row has `affected`/`fixed`.

Common Korean version phrases: `이상` = "or later" (≥), `이하` = "or earlier" (≤), `미만` = "below" (<), `초과` = "above" (>), `이전 버전` = "versions before", `모든 버전` = "all versions", `EoL`/`지원 종료` = end of life.

## Caveats

- **Fixed versions are as of the notice date.** Later patches may exist — confirm with the vendor advisory before final remediation.
- **Notices after the coverage end date are not included.** State the data cut-off in every report.
- Microsoft Patch Tuesday notices have a `Product category | CVE | CVE title` table instead of version ranges; get builds/KBs from the notice and MSRC.
- CVE lists are extracted from visible text and tables only (hidden link residue in KISA's HTML that references unrelated CVEs is ignored).
- **Risk signals**: KEV means exploitation is confirmed; EPSS is the probability of exploitation within 30 days and changes daily. Report the as-of dates (`risk_sources`) and state that not being in KEV or a low EPSS does not mean safe. CVSS stays empty until NVD data is fetched.
- Fixed versions often differ per release branch — compare within the same branch.

## Oracle notice scope (checked 2026-11-18)

KISA's Oracle notices quote only part of Oracle's release. Example: #2640 (2026-11-18, nttId 72313) against the [Oracle Critical Security Patch Update Advisory – November 2026](https://www.oracle.com/security-alerts/cspunov2026.html):

| | KISA #2640 | Oracle CSPU November 2026 |
|---|---|---|
| Scope | Java SE, JavaFX, GraalVM for JDK, GraalVM Enterprise Edition — 6 CVEs, 40 version rows | 655 new security patches across Database, Fusion Middleware (WebLogic, HTTP Server, …), MySQL, E-Business Suite, PeopleSoft, Communications, VirtualBox, Java SE, … |
| Java SE | CVE-2026-86144, CVE-2026-114938 ~ CVE-2026-114942 | 11 CVEs, all remotely exploitable without authentication. Not in KISA: CVE-2026-114943 (Hotspot, CVSS 3.1 6.5), CVE-2026-114944 (Core Java Libraries, 5.9), CVE-2026-114945 (Libraries, 5.3), CVE-2026-114946 (Compiler, 4.8), CVE-2026-114947 (JSSE, 3.7). The CVE-2026-86144 patch also fixes CVE-2026-86137 ~ CVE-2026-86143 |

- Oracle CVSS 3.1 base scores of the KISA-listed CVEs: CVE-2026-114938 8.1 (Compiler), CVE-2026-86144 7.5 (JavaFX/libxml2), CVE-2026-114939 7.4 (JGSS), CVE-2026-114940 7.4 (JSSE), CVE-2026-114941 7.0 (Compiler), CVE-2026-114942 7.0 (Libraries). [AhnLab ASEC](https://asec.ahnlab.com/ko/96614/) rates CVE-2026-114938 CVSS 4.0 9.2 (Critical): memory corruption that in some cases allows unauthenticated remote code execution.
- Oracle's notes: CVE-2026-114938, CVE-2026-114941 and CVE-2026-114942 are exploited by supplying data to APIs in the component, e.g. through a web service — server-side Java applications are in scope, not only applet/Web Start clients.
- **Java4Shell = CVE-2026-114938** (found and named by [Calif](https://calif.io/java4shell/), disclosed 2026-11-17): an out-of-bounds heap write in HotSpot's x86-64 AVX-512 Base64 decoder intrinsic. `advisory_lookup.py -q "Java4Shell"` finds it.
  - **Precondition**: the vulnerable code runs only on x86-64 CPUs with AVX-512 VBMI (Intel Xeon Ice Lake, Sapphire Rapids, Emerald Rapids, Granite Rapids; AMD Zen 4 or newer). ARM64 is not affected. Linux check (Calif): `grep -m1 '^flags' /proc/cpuinfo | tr ' ' '\n' | grep -E '^(avx512f|avx512bw|avx512vbmi|bmi2)$'` — all four flags must print.
  - **Versions**: OpenJDK 17.0.6 and later plus the 21, 25 and 27 lines, and Oracle Java 8 Performance Pack (8u511b33-perf). Standard Java 8 and 11 are not listed by OpenJDK ([Tenable](https://www.tenable.com/blog/java4shell-cve-2026-114938-frequently-asked-questions-about-openjdk-rce-vulnerability)). Calif lists OpenJDK distributions (Corretto, Temurin, Microsoft, Zulu, Liberica, SapMachine, Red Hat, …) as affected too. As of 2026-11-18 Corretto had fixed it in 17.0.21.1.2; Temurin and Red Hat had no fixed builds yet.
  - **Exploitation**: Calif demonstrated pre-auth RCE in default configurations of Keycloak, Jira, Confluence, Artifactory, Jenkins and PingFederate (product exploits withheld; the public PoC only reproduces the bug). No in-the-wild exploitation reported and not in CISA KEV as of 2026-11-18. [OX Security](https://www.ox.security/blog/java4shell-cve-2026-114938-rce-risk/) models fewer than 0.12% of JVMs as realistic RCE targets and about 0.8% as remotely crashable.
  - **Before patching** (from Calif; not in the Oracle or OpenJDK advisories): `-XX:-UseBASE64Intrinsics` (disables only the vulnerable decoder) or `-XX:UseAVX=2` (disables all AVX-512; x86-64 only — a JVM on ARM will not start with it). The Canadian Centre for Cyber Security ([AL26-029](https://www.cyber.gc.ca/en/alerts-advisories/al26-029-critical-vulnerability-impacting-oracle-java-cve-2026-114938)) recommends `-XX:UseAVX=2` and isolating internet-facing apps when patching is not possible. Confirm with `jcmd <pid> VM.flags`.
  - **Verdict aid**: in-range version plus all four CPU flags means Vulnerable. ARM64 and non-VBMI CPUs do not run the vulnerable code, but keep recommending the patch (other CVEs in the same notice, instance types can change).
- OpenJDK-based distributions: #2640 links the Amazon Corretto 17/21/25/27 changelogs, Azul Zulu release notes, and Red Hat RHSB-2026-018. Eclipse Temurin, Alpine, and Microsoft OpenJDK were "to be added" at posting time.
- ASEC's advice: until patched, review internet-facing services and block unneeded external access; after updating, restart the service and confirm the running process uses the new Java version.
- Oracle publishes security patches on the third Tuesday of every month: the quarterly cumulative CPU, and a CSPU in the other months. Next: 2026-12-15 (CSPU), 2027-01-19 (CPU), 2027-02-16 (CSPU), 2027-03-16 (CSPU).
- **#2642 (2026-11-19, nttId 72315)**: from the same November 2026 CSPU ([1] `cspunov2026`), KISA posted WebLogic Server (7 CVEs, e.g. CVE-2026-91569), E-Business Suite (Application Object Library, Concurrent Processing) and PeopleSoft Enterprise PeopleTools separately. Database, MySQL, Communications, VirtualBox and others are still missing from KISA's tables, so the rule above (check the Oracle risk matrix yourself) still applies.

## Pre-notice entries (`pre-notice.json`)

Vulnerabilities that are already public in CVE records or vendor advisories but not yet in a KISA notice. `advisory_lookup.py` merges them by date into every lookup and the briefing list (filters such as `--since`/`--type` apply to them too), labels them "KISA pre-notice entry" (type `KISA 공지 전 (벤더·CVE 원문)`, number `공지 전` in the briefing list, `--id <id>`), and drops an entry automatically once all of its CVEs appear in KISA notices; `--doctor` then lists it as retired so it can be deleted. An entry without a CVE never drops out on its own. `--doctor` warns when `checked` is more than 30 days old. The coverage line still counts KISA notices only.

- Add an entry only from primary sources (CVE record, vendor advisory, the discoverer's write-up), set `checked` to the date you read them, and use the `advisories.json` record schema with a lowercase `ntt` id and an empty `folder`. CNA scores go in `cve_meta` (`cvss`, `cvss_v`, `sev`, `cwe`, `src`); KISA-side signals win once both exist.
- Report verdicts from these entries as "vendor/CVE record, no KISA notice yet (as of `checked`)" and re-judge when KISA posts its notice.
- Keep the `skills/kesekit-advisory` and `skills-ko/kesekit-advisory-ko` copies identical (`validate-content.mjs` checks).

### NGINX2Root (checked 2026-11-19)

> **Update 2026-11-22**: KISA posted all five CVEs on 2026-11-19 as **#2641** (nttId 72314). Its fixed-version table (Open Source 1.31.9 / 1.30.7, Plus 37.3.0.1 / 37.0.8.1, no fixed version for Plus R34–R36) matches the notes below, so the nginx pre-notice entry now drops out of lookups automatically and `NGINX2Root` returns #2641. The nginx entry stays in `pre-notice.json` so that lookups keep using its F5 CVSS (`cve_meta`). The five CVEs are not in the 2026.11.20 KEV catalog either. nginx2root.com still listed no CVE for the chained kernel bug on 2026-11-22, so the `nginx2root-sctp` entry stays.

Five nginx vulnerabilities found by Theori's Xint team and named NGINX2Root ([nginx2root.com](https://nginx2root.com/)). F5, as CNA, published the CVE records on 2026-11-18 15:23 UTC (2026-11-19 00:23 KST). Xint chained each of them with a separate Linux SCTP kernel privilege escalation to reach root on the host, including from nginx running in a Docker container. `advisory_lookup.py -q "NGINX2Root"` finds the entry; the nickname also maps to the five CVEs for the KISA notice that will follow.

| CVE | Feature / config that exposes it | Type | Affected from | F5 advisory |
|---|---|---|---|---|
| CVE-2026-123007 | HTTP/2 (`listen … http2`, `http2 on`) | Integer underflow → out-of-bounds write (CWE-191, CWE-787) | 1.9.5 | K000163926 |
| CVE-2026-123634 | `proxy_pass` host with variables + `resolver`, and a `mirror` or SSI subrequest to a location that resolves the same name | Use after free (CWE-416) | 0.6.18 | K000163925 |
| CVE-2026-123633 | HTTP/2 client connections proxied to a backend (`proxy_pass`, `fastcgi_pass`, `grpc_pass`) while the worker runs low on `worker_connections` | Use after free | 1.19.7 | K000163928 |
| CVE-2026-121810 | HTTP/3 / QUIC (`listen … quic`, `http3 on`) | Use after free | 1.25.9 (the record writes "1.25.09") | K000163927 |
| CVE-2026-113425 | Mail proxy (`mail {}` with `auth_http`) | Use after free | 0.5.33 | K000163931 |

- **Scores and impact**: F5 rates every CVE CVSS 3.1 8.1 (AV:N/AC:H/PR:N/UI:N) and CVSS 4.0 9.2. F5's impact text: unauthenticated worker crash or memory corruption, code execution when ASLR is disabled or bypassed; data plane only. Xint reports a working RCE exploit for each CVE and withholds the exploits. No in-the-wild exploitation reported as of 2026-11-19 (Xint); not in CISA KEV (catalog 2026.11.17 in this data).
- **Fixed versions**: NGINX Open Source 1.31.9 (mainline) and **1.30.7 (stable)** — the Xint page names only 1.31.9. NGINX Plus 37.3.0.1 / 37.0.8.1 (CVE-2026-123633: 37.2.0.1 / 37.0.7.1). Older branches (Open Source below 1.30, Plus R33–36) are listed as affected with no fix because F5 does not evaluate End of Technical Support versions → **Vulnerable + upgrade**. On 2026-11-19 the nginx.org download server already served the 1.31.9 and 1.30.7 files, while its news, download and security-advisory pages still showed 1.31.8 / 1.30.6.
- **Credits**: CVE-2026-123007 is co-credited to Rapid7, Wiz Research, Xint and Ikotas Labs; CVE-2026-123633 to Metnir, Wiz Research and Xint; the other three to Xint.
- **Checks** (read-only):
  - Every nginx: `which -a nginx`, packages (`dpkg -l 'nginx*'`, `rpm -q nginx`), container images (`FROM nginx:…`, `docker images`), ingress controllers, appliances that bundle nginx.
  - Build: `nginx -V 2>&1` (version, `--with-http_v2_module`, `--with-http_v3_module`, `--with-mail`).
  - Loaded config: `nginx -T 2>/dev/null | grep -nE 'http2|quic|http3|^\s*mail\s*\{|auth_http|resolver|mirror|ssi\s+on|(proxy|fastcgi|grpc)_pass'`.
  - HTTP/2 from outside: `openssl s_client -connect HOST:443 -servername HOST -alpn h2 </dev/null 2>&1 | grep -F 'ALPN protocol: h2'` (no output only counts when the TLS handshake itself succeeds).
- **Verdict aid**: an in-range version is Vulnerable whatever features are on (patch anyway). It is Critical when an exposing feature is reachable from the internet (HTTP/2 or HTTP/3 listener, mail proxy, resolver + mirror/SSI). Distribution packages, images and appliances may carry a backported fix under the old version string → Needs review until the distribution or vendor advisory confirms. A CDN or load balancer that terminates HTTP/2 and speaks HTTP/1.1 to nginx blocks the HTTP/2 path only when nginx is not reachable directly (not with TLS passthrough). Internal-only servers still need the patch.
- **Remediation**: update, then **restart** — `nginx -s reload` keeps the old binary; confirm that no old worker processes remain. Until then, disable HTTP/2 on every listener (`http2 off;` on 1.25.1 and later; remove `http2` from `listen` on 1.9.5–1.25.0), which covers only CVE-2026-123007 and CVE-2026-123633 and stops gRPC over HTTP/2. HTTP/3, resolver/mirror/SSI and the mail proxy need their own review. WAF rules do not cover HTTP/2 frame handling.
- **Investigation**: access logs do not record `WINDOW_UPDATE` / `RST_STREAM` frames. Look at error logs (repeated worker crashes), unexpected child processes of nginx workers, and network captures. On a confirmed compromise, rotate secrets the worker could read and check the host, since the chain reaches root.
- **Kernel**: the Linux SCTP privilege escalation has no CVE or patch yet (Xint: "in the coming weeks"). Patching nginx closes the way in; track the kernel fix separately. It is its own entry (`--id nginx2root-sctp`, no CVE, flagged "fix not released") so it stays when the nginx CVEs reach a KISA notice; add its CVE to `cves` once one is assigned. If SCTP is unused, blocking the module (`lsmod | grep sctp`; `install sctp /bin/false` in `/etc/modprobe.d/`) is general hardening, not a confirmed mitigation for this bug.
- Sources: CVE records on cve.org (read 2026-11-19), F5 K000163925 / K000163926 / K000163927 / K000163928 / K000163931, [nginx2root.com](https://nginx2root.com/), nginx.org download server.
