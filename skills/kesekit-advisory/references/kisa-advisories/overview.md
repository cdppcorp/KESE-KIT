# KISA Security Notice Data Overview

Structured data collected from the KISA Boho-nara (KrCERT/CC) security notice board. It backs exposure checks, notice briefings, CVE lookups, and threat-response checks.

## Source

- Board: KISA Boho-nara security notices — https://www.boho.or.kr/kr/bbs/list.do?bbsId=B0000133&menuNo=205020
- Archive in this repo: `문서/KISA_보안공지_2025-2026/` (`목록.csv` index + per-notice `본문.html`/`본문.txt`/attachments)
- Notices are published in Korean. Titles, summaries, and table cells stay in Korean; product names, versions, and CVE IDs are language-neutral.

## Notice types and how this skill uses them

| Type (Korean label) | Meaning | Used for |
|---------------------|---------|----------|
| 보안 업데이트 권고 (Security update advisory) | Vendor patch release. Usually has a `CVE \| Product \| Affected versions \| Fixed versions` table | Exposure check (`advisories.json`) |
| 취약점 조치 권고 (Vulnerability mitigation advisory) | Interim mitigations, security-software clean-up, response rules (e.g. PHP2Shell, FreeType) | Exposure check + threat response |
| 보안 조치·강화 권고 (Hardening advisory) | Incident / malware response checks (BPFDoor, Linux kernel rootkits, ransomware, exposed credentials, …) | Threat response (`threat-response.md`) |
| 주의 권고 (Caution advisory) | Product-use cautions (EoL / stop using), dev supply-chain attacks, phishing/smishing | Threat response |
| 기타 (Other) | US CISA KEV sharing, impersonation case reports | Reference |

## advisories.json schema (schema 1)

```
{
  "schema": 1,
  "source": "...",
  "coverage": {"first": "YYYY-MM-DD", "last": "YYYY-MM-DD", "count": N},
  "advisories": [            ← newest first, one notice per line
    {
      "no": "2632",           ← Boho-nara post number ("공지" for pinned posts)
      "ntt": "72304",         ← nttId from the source URL (unique key, accepted by --id)
      "date": "2026-11-12",
      "type": "보안 업데이트 권고",
      "title": "Apache 제품 보안 업데이트 권고",
      "vendor": "Apache",     ← vendor normalised from the title ("기타" = unclassified)
      "url": "https://www.boho.or.kr/...",
      "folder": "2026/11/...",
      "attachments": [],
      "summary": "Description section, max 500 chars",
      "cves": ["CVE-..."],
      "affected": [           ← notice tables flattened per row (rowspan/colspan expanded)
        {"cve": "...", "vendor": "...", "product": "...", "ecosystem": "npm",
         "affected": "2.4.55 이상 2.4.71 미만", "fixed": "2.4.71 이상",
         "severity": "...", "description": "..."}
      ],
      "text": "body text (URLs removed, max 4000 chars) — for finding products mentioned outside the table",
      "tables": [{"header": [...], "rows": [[...]]}]   ← tables whose columns could not be mapped (optional)
    }
  ]
}
```

A row only carries the columns its table had; not every row has `affected`/`fixed`.

Common Korean version phrases: `이상` = "or later" (≥), `이하` = "or earlier" (≤), `미만` = "below" (<), `초과` = "above" (>), `이전 버전` = "versions before", `모든 버전` = "all versions", `EoL`/`지원 종료` = end of life.

## Caveats

- **Fixed versions are as of the notice date.** Later patches may exist — confirm with the vendor advisory before final remediation.
- **Notices after the coverage end date are not included.** State the data cut-off in every report.
- Microsoft Patch Tuesday notices have a `Product category | CVE | CVE title` table instead of version ranges; get builds/KBs from the notice and MSRC.
- CVE lists are extracted from visible text and tables only (hidden link residue in KISA's HTML that references unrelated CVEs is ignored).
- Fixed versions often differ per release branch — compare within the same branch.

## Source data quality notes (reviewed 2026-11-14)

- **Misplaced attachment**: the PDF in folder `2026/07/2026-07-21_2500_…` is the same file (matching SHA-256) as the one in `2026/09/2026-09-29_2551_…`. Notice #2500's real attachment was not collected, and its attachment name in `목록.csv` is wrong too.
- **Truncated body**: #2222's `본문.txt`/`본문.html` stop in the middle of reference item (8).
- **Truncated folder names**: 19 folder names are cut at about 40 characters (e.g. 2116, 2155, 2292, 2581); in 2315, 2433 and 2467 `/` or `"` was replaced with `_`. Always resolve paths through the `폴더경로` column of `목록.csv`.
- **Pinned notices**: 5 rows have number `공지`, two of them on the same date (2026-07-16). Key them on the `nttId` in the source URL.
- **Attachments replaced after posting**: the PDFs of #2241, #2244, #2322 (rev1), #2378 and #2559 are later revisions.
- **Errors in KISA's own text**: #2551 writes the reporting site as `conterscam112.go.kr` (other notices: `counterscam112.go.kr`); step cross-references in the BPFDoor guide do not line up.

## Refreshing the data

1. Add new notice folders and `목록.csv` rows under `문서/KISA_보안공지_2025-2026/KISA_보안공지_2025-2026/`.
2. Build from the repository root. This regenerates `advisories.json`, `vendor-index.md`, and this file's statistics block for both EN and KO skills.
   ```bash
   python scripts/build_kisa_advisories.py
   # different source location: python scripts/build_kisa_advisories.py --source "<folder with 목록.csv>"
   ```
3. If new 보안 조치·강화 권고 / 취약점 조치 권고 / 주의 권고 notices appeared, add TR items to `threat-response.md` (EN/KO).
4. Validate with `node scripts/validate-content.mjs`.
